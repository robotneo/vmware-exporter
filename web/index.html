Endpoints

This exporter collects metrics from VMware vCenter Server and from standalone ESXi hosts. The target type is detected at login, so the same endpoint serves both.

Reference

Single target mode

Start the exporter with the target and its credentials, then let Prometheus scrape /metrics:

./vmware-exporter \
  -vmware.vcenter=vcenter.example.com \
  -vmware.username=admin@vsphere.local \
  -vmware.password=secret \
  -vmware.insecureTLS=true

The same flags work against a standalone ESXi host. There is no separate mode to select: the exporter reads ServiceContent.About.ApiType at login and adapts, because a lone host has no real datacenter or cluster objects to walk.

Passwords on the command line are visible to anyone who can run ps or read /proc. Prefer -envflag.enable with an environment file.
Timing flags
FlagDefaultEffect
-vmware.timeout60Overall budget in seconds for one scrape, covering login, property retrieval and performance sampling. Raise it for large inventories.
-vmware.interval20PerfManager sampling window in seconds. Independent of the scrape timeout.
-vmware.granularity20Sampling frequency in seconds. Must be greater than 0 and no larger than the interval.
Multi target mode

Required parameters: target, username, password. Optional: schema (defaults to https), insecure=true to skip TLS verification.

Credentials may also arrive as HTTP Basic Auth instead of URL parameters.

Basic Auth collides with -web.config.file. When the exporter's own listener has basic_auth_users configured, it consumes the Authorization header itself, so vCenter credentials cannot travel that way. Use URL parameters, or the debug console, which posts them as a form body.

Collectors are selected with repeatable collect[] and nocollect[] parameters:

# default collectors only
/probe?target=vcenter.example.com&username=admin&password=secret&insecure=true

# only VM and host metrics
/probe?target=...&collect[]=vm&collect[]=host

# everything
/probe?target=...&collect[]=all

# everything except the esxcli collectors
/probe?target=...&collect[]=all&nocollect[]=esxcli.host.nic&nocollect[]=esxcli.storage

A misspelled collector name is rejected with HTTP 400 and the list of valid names, rather than silently producing an empty metric set.

Prometheus configuration

Different collectors for different vCenters, with credentials carried in the service discovery file rather than the scrape config:

scrape_configs:
  # Production vCenter - all collectors
  - job_name: 'vmware-prod'
    scrape_interval: 60s
    metrics_path: /probe
    file_sd_configs:
      - files: ['/etc/prometheus/targets/vmware_prod.yml']
    params:
      schema: ['https']
      insecure: ['true']
      collect[]: ['all']
    relabel_configs:
      - source_labels: [__meta_username]
        target_label: __param_username
      - source_labels: [__meta_password]
        target_label: __param_password
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: localhost:9169

  # Dev vCenter - basic collectors only, scraped less often
  - job_name: 'vmware-dev'
    scrape_interval: 120s
    metrics_path: /probe
    file_sd_configs:
      - files: ['/etc/prometheus/targets/vmware_dev.yml']
    params:
      schema: ['https']
      insecure: ['true']
      collect[]: ['datacenter', 'host', 'vm']
    relabel_configs:
      - source_labels: [__meta_username]
        target_label: __param_username
      - source_labels: [__meta_password]
        target_label: __param_password
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: localhost:9169
